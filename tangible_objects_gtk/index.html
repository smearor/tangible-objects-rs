Daemon-embedded GTK visualization (concepts/planned/GUI.md + WORKSPACE.md Phase 3).

Embedded library, not a remote client: the embedding daemon calls run_gui, which runs the engine/device loop on a background thread (in-process, zero-latency event flow) and renders the SharedState in the GTK main loop. Daemon-mode semantics (interfaces, control commands, recording, calibration) arrive via GuiHooks so this crate never links the daemon crate.

BackgroundAlpha
Canvas background opacity (0.0-1.0) - the alpha the cairo fill applies, not a window-opacity hint: touches, figures and UI chrome stay opaque at any value.
GuiHooks
Mode plumbing the embedding daemon supplies: the GUI owns the device loop like the headless modes do, but control-command draining, recording status and interface spawning stay the daemon’s semantics - injected as function pointers instead of a daemon dependency.
GuiOptions
Display-side options for crate::run_gui - window presentation, not detection behavior (DetectionConfig stays on the engine side).
SharedState
Snapshot the draw functions consume - written by the device thread once per SYN_REPORT frame, read by the ~30 fps GTK timer.
