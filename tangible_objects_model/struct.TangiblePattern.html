Expand description

A tangible figure pattern defined by invariant pairwise distances.

For n points the fingerprint consists of all n*(n-1)/2 pairwise distances, sorted ascending. Matching compares a measured distance set against the fingerprint within a tolerance, which makes the fingerprint position- and rotation-invariant.

Fields§

§id: PatternId

Runtime ID assigned when the profile directory is loaded.

§name: PatternName

Human-readable figure name (from the profile file).

§enabled: bool

Whether the pattern participates in matching (SetProfileEnabled command). Disabled patterns stay registered but produce no matches and spawn no tangibles.

§spawn_on_partial: bool

Whether a partial match may spawn this tangible (SPAWN_AS_PARTIAL.md); the incumbent path ignores the flag.

§spawn_stability: FrameCount

Frames a partial spawn must hold before the tangible leaves pending state.

§num_points: PinCount

Number of contact pins the figure must have.

§sorted_distances: Distances

Sorted pairwise distances of the reference point set (the fingerprint).

§tolerance: PatternTolerance

Maximum allowed deviation per distance during matching.

§tolerances: PatternTolerances

Optional per-distance tolerances, parallel to sorted_distances. When empty (or length-mismatched), the scalar tolerance applies to every index - the recorded p99 suggestions from the analysis crate are written here.

§ref_points: Option<RefPoints>

Original reference point positions, if stored in the profile. Required for partial matching when one contact pin is missing.

§regions: Vec<Region>

Detection regions restricting where this figure may match (PROFILE_REGIONS.md). Empty = anywhere on the surface.

§stage: Option<StageName>

Pipeline stage this pattern suppresses through (EVENT_PIPELINE.md). None = the general stage.

Whether points may match spatially: every point must lie inside the union of this pattern’s Regions. With no regions configured every position is accepted.

Source

pub fn tolerance_at(&self, index: usize) -> PatternTolerance

The effective tolerance for distance index i: the per-index value when tolerances is configured, else the scalar tolerance.

Source

pub fn matches(&self, points: PointSet<'_>) -> bool

Checks whether a set of measured points matches this pattern exactly.

Each deviation is compared against its per-index tolerance (Self::tolerance_at); the scalar tolerance is the fallback when no tolerances vector is configured.

Source

pub fn footprint(&self) -> Millimeters

The pattern’s spatial footprint - the largest span a matching candidate’s pairwise diameter may reach, max_ij(s_ij + tol_ij) (SPATIAL_CLUSTERING.md). Combinations spanning more than this can never satisfy the distance fingerprint; the matcher prunes them before evaluation.

Source

pub fn match_score(&self, points: PointSet<'_>) -> MatchScore

Normalized deviation score of a measured fingerprint: the largest deviation-to-tolerance ratio across all distance indices.

score <= 1.0 is equivalent to Self::matches on the same point set - but the score additionally ranks candidates (lower is closer) and quantifies near-misses, which the score-based matcher and the offline analysis use.

Source

pub fn build_match( &self, points: PointSet<'_>, combo: Combination<'_>, partial: bool, claimed: ClaimedIndices, ) -> PatternMatch

Builds the PatternMatch for a matched point combination: centroid center, rotation_of estimate (replaced later for exact winners via PatternMatch::resolve_correspondence), and the (partial) name marker on reduced-fingerprint matches.

Source

pub fn try_exact( &self, combo: Combination<'_>, touches: TouchSet<'_>, completion: &CompletionConfig, ) -> Option<PatternMatch>

Incumbent re-match on bound slots (TRACKING_STABILIZATION.md): combo is verified against the affinity-scaled score (match_score <= factor) - the slot binding already proves identity, so motion distortion must not lose the match.

Source

pub fn try_partial( &self, combo: Combination<'_>, touches: TouchSet<'_>, completion: &CompletionConfig, pool: ClaimPool<'_>, ) -> Option<PatternMatch>

Like Self::try_exact for a partial (num_points - 1) combination; also claims the predicted missing pin(s) from pool when completion is enabled.

Source

pub fn claim_missing( &self, kept_refs: &RefIndices, points: PointSet<'_>, combo: Combination<'_>, pool: ClaimPool<'_>, touches: TouchSet<'_>, completion: &CompletionConfig, ) -> ClaimedIndices

Claims the predicted positions of a partial match’s missing pins (TRACKING_STABILIZATION.md).

kept_refs are the reference indices that matched; points/combo the measured points. For every missing reference pin the expected position is predicted via Self::predict_missing and the nearest free touch inside radius_factor × tolerance is claimed.

Source

pub fn score_of(&self, deviations: &Deviations) -> MatchScore

Score of an already-computed deviation vector - max_i dev[i] / tolerance_at(i); 0.0 for empty or length-mismatched input.

Source

pub fn match_error(&self, points: PointSet<'_>) -> MatchError

Total absolute deviation across all distances (lower is better).

Source

pub fn deviations(measured: &Distances, reference: &Distances) -> Deviations

Absolute per-index deviation between a measured and a reference fingerprint; empty when the lengths differ.

Source

pub fn partial_tolerance(&self) -> Millimeters

Widened acceptance tolerance for partial (missing-pin) matches - a reduced fingerprint needs more slack than an exact one (SPAWN_AS_PARTIAL.md): self.tolerance unscaled.

Source

pub fn partial_reference(&self, skip: RefIndex) -> Option<PartialReference>

Fingerprint of the reference point set with pin skip removed.

Returns the kept reference indices and their sorted pairwise distances; None when no reference points are stored, their count differs from num_points or skip is out of range.

Source

pub fn partial_reference_multi( &self, skips: &RefIndices, ) -> Option<PartialReference>

Like Self::partial_reference with skips pins removed - needed for num_points - 2 completion candidates.

Source

pub fn matches_partial(&self, points: PointSet<'_>) -> Option<PartialMatch>

Partial match: tests whether points (num_points - 1 contacts) fit a subset of the reference points with one pin missing (e.g. a tilting object). Every possibility of dropping one reference point is tried. The scalar tolerance is raised by 50% to account for the higher uncertainty - per-index tolerances cannot apply here because dropping a pin re-indexes the distance fingerprint.

Returns the matched reference indices and the total error.

Source

pub fn matches_partial_missing( &self, points: PointSet<'_>, missing: usize, ) -> Option<PartialMatch>

Generalized partial match with missing dropped pins (1 or 2). The returned indices are the kept reference points, ordered like the reference - the complement are the missing pins, used by missing-pin completion to predict their expected positions.

Source

pub fn matches_partial_missing_scaled( &self, points: PointSet<'_>, missing: usize, tol_scale: AffinityFactor, ) -> Option<PartialMatch>

Like Self::matches_partial_missing, with the partial tolerance scaled by tol_scale - incumbent re-matching relaxes the threshold (slot binding already proves identity); 1.0 keeps the default.

Source

pub fn predict_missing( &self, kept_refs: &RefIndices, measured: PointSet<'_>, missing: RefIndex, ) -> Option<Vec2<Millimeters>>

Predicts the screen position of a missing reference pin from a partial match’s geometry.

kept_refs are the reference indices that matched (from Self::matches_partial_missing); measured are the frame positions of the kept pins in the same order. The missing pin’s expected position is estimated by fitting a rigid transform (rotation + translation, no scale) ref→measured.

Returns None when the correspondence between kept reference and measured points is ambiguous within tolerance.
