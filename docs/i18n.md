# Localization (i18n)

User-facing surfaces are localized with Fluent (I18N.md). The
translation assets live in the workspace-root `i18n/` directory - shared
by the embedded GUI and the TUI, embedded at compile time via
`rust-embed`.

```
i18n/
├── de/tangible-objects-gtk.ftl
├── de/tangible-objects-tui.ftl
├── en/tangible-objects-gtk.ftl   (fallback language)
└── en/tangible-objects-tui.ftl
```

## Mechanism

Each surface crate (`tangible-objects-gtk`, `tangible-objects-tui`)
holds a `LazyLock<FluentLanguageLoader>`:

- `fluent_language_loader!()` declares the fallback (`en`).
- `DesktopLanguageRequester::new().requested_languages()` reads the
  desktop locale chain (`LANGUAGE`/locale settings).
- `i18n_embed::select` picks the best match from the embedded assets; a
  failed select silently keeps the fallback - a missing locale is never
  a runtime error.
- Strings are referenced as `fl!(language_loader(), "message-id")`
  (`i18n-embed-fl`); Fluent variables render as
  `fl!(loader, "id", "name" => value)` where applicable.

## Adding a string

1. Add `id = Text` to the `.ftl` file of **every** locale directory
   (missing ids fall back to the id itself at render time).
2. Reference it with `fl!` - the loader is exported per crate
   (`gtk::i18n::language_loader`, the TUI's own `i18n` module).

## Scope

| Surface | Localized? | Asset |
|---------|-----------|-------|
| Embedded GUI (`--gui`) | yes | `tangible-objects-gtk.ftl` |
| TUI | yes | `tangible-objects-tui.ftl` |
| Daemon console output (`--live`/`--filter`/…) | no - single-language diagnostics | - |
| GraphQL/D-Bus/MCP payloads | no - wire data, client renders | - |
